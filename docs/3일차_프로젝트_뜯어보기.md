# 3일차 - 프로젝트 템플릿 뜯어보기

## 1. 각 디렉터리의 역할 및 작성할 파일 내용

프로젝트는 **관심사의 분리(Separation of Concerns)** 원칙을 기반으로 아래와 같은 디렉터리 구조로 구성됩니다.

```
ah_web_development/
├── alembic/                    # DB 마이그레이션 관련 파일
│   ├── env.py                  # Alembic 실행 환경 설정
│   ├── script.py.mako          # 마이그레이션 스크립트 템플릿
│   └── versions/               # 생성된 마이그레이션 파일들
├── app/
│   ├── apis/                   # API 라우터 (엔드포인트 정의)
│   │   └── practice_apis.py    # 연습용 CRUD API 라우터
│   ├── core/                   # 핵심 설정 및 공통 모듈
│   │   ├── config.py           # 환경변수 기반 앱 설정
│   │   └── db/
│   │       ├── databases.py    # DB 엔진 및 세션 설정
│   │       └── models.py       # 공통 Mixin 모델 (UUID, Timestamp, SoftDelete)
│   ├── models/                 # SQLAlchemy ORM 모델 (DB 테이블 정의)
│   │   └── user_models.py      # 현재는 Pydantic 모델 (추후 ORM 모델로 교체)
│   ├── repositories/           # DB CRUD 로직 (쿼리 수행 레이어)
│   ├── schemas/                # Pydantic 스키마 (요청/응답 데이터 검증)
│   ├── services/               # 비즈니스 로직 레이어
│   │   ├── authentication.py   # 이메일/비밀번호 인증 로직
│   │   └── user_services.py    # 사용자 관련 서비스 로직
│   └── main.py                 # FastAPI 앱 진입점, 라우터 등록
├── docs/                       # 프로젝트 문서
├── media/                      # 사용자 업로드 파일 저장 디렉터리
├── static/                     # 정적 파일 (CSS, JS, HTML)
├── .env.example                # 환경변수 예시 파일
├── alembic.ini                 # Alembic 설정 파일
├── docker-compose.yml          # Docker Compose 설정
└── pyproject.toml              # 프로젝트 의존성 및 설정
```

### 각 디렉터리의 역할

| 디렉터리 | 역할 |
|---------|------|
| `apis/` | HTTP 요청을 받는 라우터(엔드포인트)를 정의. URL과 HTTP 메서드를 연결하고 요청을 처리해 응답 반환 |
| `core/` | 앱 전체에서 공통으로 사용하는 설정과 유틸리티. DB 연결 설정, 공통 Mixin 클래스 등 포함 |
| `models/` | SQLAlchemy ORM을 사용하여 DB 테이블 구조를 Python 클래스로 정의 |
| `repositories/` | DB와 직접 상호작용하는 CRUD 쿼리 함수들을 모아두는 계층. 데이터 액세스 로직을 캡슐화 |
| `schemas/` | API 요청(Request)/응답(Response)의 데이터 형식을 Pydantic으로 정의. 데이터 유효성 검증 담당 |
| `services/` | 비즈니스 로직을 처리하는 계층. Repository를 호출하고 복잡한 로직 수행 |

## 2. 각 파일의 역할

### `app/main.py`
FastAPI 애플리케이션의 **진입점(Entry Point)**입니다.
- `FastAPI()` 인스턴스를 생성
- 각 모듈의 라우터를 `include_router()`로 등록
- `static`, `media` 디렉터리를 정적 파일 마운트
- 헬스체크 엔드포인트 제공
- SPA(Single Page Application)를 위한 catch-all 라우트 설정

### `app/core/config.py`
`pydantic-settings`의 `BaseSettings`를 활용한 **환경변수 관리** 파일입니다.
- `.env` 파일에서 환경변수를 자동으로 로드
- DB 접속 정보(호스트, 포트, 사용자명, 비밀번호, DB명)를 관리
- 코드에 민감한 정보를 하드코딩하지 않도록 도와줌

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DB_USER: str = "root"
    DB_PASSWORD: str = "password1234"
    DB_HOST: str = "localhost"
    DB_PORT: str = "3306"
    DB_NAME: str = "ai_health"

    model_config = {"env_file": ".env", "extra": "ignore"}

settings = Settings()
```

### `app/core/db/databases.py`
**SQLAlchemy 비동기 DB 엔진 및 세션**을 설정하는 파일입니다.
- `create_async_engine`: 비동기 DB 연결 엔진 생성 (`asyncmy` 드라이버 사용)
- `async_sessionmaker`: 비동기 세션 팩토리 생성
- `declarative_base()`: ORM 모델의 기반이 되는 `Base` 클래스 생성
- `async_get_db()`: FastAPI `Depends`에 사용할 세션 생성 제너레이터

### `app/core/db/models.py`
SQLAlchemy ORM 모델에서 공통으로 사용하는 **Mixin 클래스** 모음입니다.
- `UUIDMixin`: 모든 테이블의 PK를 UUID7 형식의 CHAR(36)로 정의
- `TimestampMixin`: `created_at`, `updated_at` 타임스탬프 컬럼 자동 추가
- `SoftDeleteMixin`: `deleted_at`, `is_deleted` 컬럼을 추가하여 논리적 삭제 지원

### `alembic/env.py`
Alembic 마이그레이션 실행 환경을 설정하는 파일입니다.
- 비동기 엔진 `async_engine_from_config` 사용
- `target_metadata = Base.metadata`로 ORM 모델 메타데이터 연결
- `run_migrations_online()`: DB와 연결하여 온라인 방식으로 마이그레이션 실행

## 3. 데이터베이스 연결 설정

본 프로젝트는 **MySQL**을 데이터베이스로 사용하며, **비동기(async) 방식**으로 연결합니다.

### 연결 흐름

```
.env 파일
    ↓ (환경변수 로드)
app/core/config.py (Settings)
    ↓ (DB 접속 정보 제공)
app/core/db/databases.py
    ↓ (DATABASE_URL 생성)
mysql+asyncmy://user:password@host:port/dbname
    ↓
create_async_engine() → async_engine
    ↓
async_sessionmaker() → AsyncSessionLocal
    ↓
async_get_db() → DB 세션 (Depends로 주입)
```

### 드라이버: `asyncmy`
MySQL 비동기 드라이버로, `asyncio` 기반의 FastAPI와 함께 사용합니다.
동기 드라이버(`mysqlclient`, `PyMySQL`)와 달리 이벤트 루프를 블로킹하지 않아 높은 동시성 처리가 가능합니다.

### 세션 사용 예시

```python
from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession
from app.core.db.databases import async_get_db

@router.get("/users")
async def get_users(db: AsyncSession = Depends(async_get_db)):
    # db를 이용해 쿼리 수행
    result = await db.execute(select(User))
    return result.scalars().all()
```

## 4. SQLAlchemy를 활용한 모델 작성 및 Alembic 마이그레이션 방법

### SQLAlchemy ORM 모델 작성

SQLAlchemy 2.0의 **Mapped / mapped_column** 방식을 사용하여 타입 힌트 기반으로 모델을 작성합니다.

```python
from sqlalchemy import String, Integer
from sqlalchemy.orm import Mapped, mapped_column
from app.core.db.databases import Base
from app.core.db.models import UUIDMixin, TimestampMixin, SoftDeleteMixin

class User(UUIDMixin, TimestampMixin, SoftDeleteMixin, Base):
    __tablename__ = "users"

    name: Mapped[str] = mapped_column(String(10), nullable=False)
    email: Mapped[str] = mapped_column(String(100), unique=True, nullable=False)
    hashed_password: Mapped[str] = mapped_column(String(255), nullable=False)
```

### Alembic 마이그레이션 절차

```bash
# 1. 마이그레이션 파일 자동 생성 (모델 변경 후)
uv run alembic revision --autogenerate -m "마이그레이션 설명"

# 2. 마이그레이션 DB에 적용
uv run alembic upgrade head

# 3. 마이그레이션 되돌리기
uv run alembic downgrade -1

# 4. 현재 마이그레이션 상태 확인
uv run alembic current
```

### 주의사항
- 새로운 모델 파일을 생성한 후, `alembic/env.py`의 `from app import models` 또는 각 모델 파일을 import해야 Alembic이 변경사항을 감지합니다.
- `Base.metadata`에 모든 모델이 등록되어 있어야 `--autogenerate`가 정상 동작합니다.

## 5. API 구현 흐름

FastAPI에서 하나의 API 엔드포인트가 요청을 처리하는 전체 흐름입니다.

```
클라이언트 요청 (HTTP Request)
        ↓
  [Router / apis/]
  - URL 매핑 및 HTTP 메서드 정의
  - Request Body / Query Parameter를 Schema로 검증
  - Depends를 통해 DB 세션 주입
        ↓
  [Service / services/]
  - 비즈니스 로직 처리
  - 인증, 권한 검사, 데이터 가공 등 수행
  - Repository 호출
        ↓
  [Repository / repositories/]
  - SQLAlchemy를 통해 DB에 쿼리 실행
  - ORM 모델을 조회/생성/수정/삭제
        ↓
  [DB / MySQL]
  - 실제 데이터 저장 및 조회
        ↑
  [Schema (Response)]
  - DB에서 받아온 ORM 객체를 Pydantic 스키마로 변환
  - 클라이언트에 JSON 형식으로 응답
```

### 각 계층의 역할 요약

| 계층 | 파일 위치 | 역할 |
|------|----------|------|
| **Router** | `apis/` | HTTP 요청 수신, 라우팅, 스키마 검증 |
| **Schema** | `schemas/` | 요청/응답 데이터 형식 정의 (Pydantic) |
| **Service** | `services/` | 비즈니스 로직, 인증/권한, 데이터 가공 |
| **Repository** | `repositories/` | DB CRUD 쿼리 수행 |
| **Model** | `models/` | DB 테이블 구조 정의 (SQLAlchemy ORM) |

### 의존성 주입 (Dependency Injection)

FastAPI의 `Depends`를 활용하여 DB 세션, 인증 정보 등을 자동으로 주입합니다.

```python
# 의존성 주입 예시
@router.post("/patients")
async def create_patient(
    data: PatientCreateSchema,          # 요청 Body 스키마 검증
    db: AsyncSession = Depends(async_get_db),  # DB 세션 자동 주입
    current_user = Depends(get_current_user),  # 로그인 사용자 정보 주입
):
    return await patient_service.create(db, data, current_user)
```

이러한 계층 분리 구조를 통해:
- **테스트 용이성**: 각 계층을 독립적으로 테스트 가능
- **코드 재사용성**: Service, Repository를 여러 API에서 재사용 가능
- **유지보수성**: 변경사항이 특정 계층에만 영향을 미침
